# Google AI Music Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; tests before implementation.

**Goal:** Add Google AI Studio/Lyria to MIXVERSE music and singing workflows.
**Architecture:** An httpx Interactions adapter plugs into the existing provider endpoint; backend capability metadata drives provider-specific frontend text. Existing local music and optional legacy ElevenLabs stay usable.
**Tech Stack:** Python/FastAPI/httpx, React/TypeScript/Vitest.
**Spec:** ../specs/2026-10-30-google-ai-design.md

## Global Constraints
- No real generation/API charges during automated tests.
- Secrets only in backend environment; no retry of generation POSTs.
- Google default lyria-3.5; clip requests only 30 seconds.
- Existing task-owned clone is the isolated working copy; branch codex/google-ai-music.

## Review Focus
- Missing or whitespace key must not enable paid generation.
- Malformed/no audio must not create a playable result or leave partial files.
- Timeout/billing/rate/auth errors must be distinguishable without leaking provider responses.
- Consent and optional access token must be enforced before outgoing requests.
- Google labels/consent/library attribution must survive both music and song flows.
